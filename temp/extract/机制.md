## A. 对象模型（由规则反推，非原文）

- Character：hp、maxHp、atk、skills[]、items[]、owner(先手/后手)、slot(1..5)、flags{已救援次数、濒死、无敌、免疫…}
- Skill：name、type(battlecry/charge/cooldown/active/passive)、cost(充能层数/耐久)、durability、cd、initialCd、text
- Item：name、cost(道具花费)、timing、text
- Player：side、characters[]、resources{费用 14k}、itemBar[]、bans{pick/ban}
- GameState：turn(大回合)、phase(先手/后手)、eventQueue、winner

两个时间单位必须区分（R15/R34）：
- 小回合（半回合）：先手回合 或 后手回合。
- 大回合：先手回合 + 后手回合，即“一回合”。

## C. 结算顺序算法（R21）

1. 收集本次触发的所有“待结算效果”，每条标记 affectedCharacter。
2. 按 slot 交错排序：先手 n 与 后手 n 交替，n 从 1 递增。
3. 同一角色内部按来源优先级排序：本角色特性/技能 > 己方道具、技能 > 敌方效果。
4. 同级内按“附带效果的先后顺序、技能顺序”稳定排序（保持插入序）。
5. 逐个结算；结算中断（死亡/免疫）需重新筛选后续目标。

实现建议：效果队列 + 稳定排序键 `(slot, sideRank, sourceRank, seq)`。

## D. 胜负判定状态机（R25）

优先级从高到低：
1. 单方全员死亡 → 另一方胜。
2. 双方全员死亡（反伤等） → “主动触发该局面的一方”胜（需记录 lastActionSource）。
3. 双方均无获胜手段 → 记录该局面由谁造成 → 该方胜 `[Q]` 判定标准。
4. 双方都有进攻手段但均不主动进攻 → 计满 4 个小回合后，最后主动进攻方胜。
5. 一方有进攻手段、另一方没有 → 计满 2 个大回合后，**无法进攻方胜**。
6. “进攻”定义：使用能造成伤害或减益的任意操作。
